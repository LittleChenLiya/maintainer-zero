# Maintainer-Zero 架构与演进边界

## 产品契约

用户提供仓库与事故参数，获得一份可复查的连续性演练报告：依据是什么、哪些环节可能阻塞、还缺什么证据、下一步该验证什么。报告不是对维护者能力的评价，也不是事故概率预测或安全认证。

首版采用 **Python 标准库 + 本地 Git CLI + 确定性场景函数**。不要求模型 API、数据库或服务端。这样首次运行成本低，仓库内容可以留在本机，评分变化也能在代码审查中解释。

## 当前代码结构

```text
CLI 参数
  └─ analyzer.snapshot_repository → RepoSnapshot
       └─ scenarios.SCENARIOS → DrillResult[]
            └─ report.write_report → JSON / Markdown / HTML
```

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| `cli.py` | 参数解析、场景选择、报告输出 | 不承担风险规则 |
| `analyzer.py` | 提取 Git 历史、依赖名、CODEOWNERS 和配置存在性 | 不执行待分析仓库的代码 |
| `models.py` | 快照、发现与结果的数据结构 | 不依赖界面或外部 API |
| `scenarios.py` | 纯函数演练与可解释发现 | 不联网、不写文件、不读取系统时间 |
| `report.py` | 把同一结果转换为三种工件，并输出 GitHub 元数据证据状态与隐私边界摘要 | 不重算或修改评分；隐私摘要只记录布尔状态，不保存身份映射 |
| `manifest.py` | 为已生成的本地工件写入 bounded SHA-256/size manifest，并离线校验 | 只允许相对路径与普通文件；manifest 不包含自身 hash，不是数字签名 |
| `fallback.py` | 校验 data-only 依赖替代/冷构建计划并生成未执行声明摘要 | 不执行命令、不联网；`planned`/`passed` 仅是声明，不能当作运行证明 |
| `benchmark.py` | 将已验证报告投影为隐私保护的公开基准摘要，并校验待分享摘要 | 省略仓库/人员身份、依赖名、Finding 文本和原始记录；`validate-benchmark` 只读、离线、不形成排名 |
| `github_metadata.py` | 校验并摘要 provider-neutral 的只读元数据快照 | 允许 github/gitlab/forgejo provider；共用规范化资源白名单与 unknown/partial 语义；不联网、不认证、不执行适配器 |
| `metadata_mapping.py` | 将经审阅的 provider 原始数据映射为 canonical 快照 | 仅使用显式资源/字段别名和标量白名单；冲突、未知键、嵌套值与凭证 fail-closed；不联网、不认证、不执行代码 |
| `metadata_provider.py` | 通过调用方注入的 GET transport 采集 GitLab/Forgejo 有界元数据 | 仅生成显式白名单路径；限制项目标识、分页、超时、响应大小和限流提示；输出先投影再 canonical 校验；不内置网络、token 或写操作 |
| `provider_http.py` | 为 GitLab/Forgejo 提供显式 opt-in 的 HTTPS GET transport | 仅 HTTPS、固定路径、GET、无重定向和白名单响应头；token 仅显式环境 opt-in；不自动重试、不执行或写入远端 |
| `.github/workflows/continuity.yml` | 在本项目 CI 中运行并上传报告 | 默认只读仓库权限 |

数据流必须保持单向：采集层不能为获得好看的分数补造事实，报告层不能把未知状态改写成“安全”。GitHub 元数据证据只作为上下文，除非场景明确声明输入契约，否则不参与分数计算。

`validate-fallback-plan` 是 fallback 计划的独立只读审阅入口；它与 `simulate --fallback-plan` 共用同一严格 loader，便于在 CI 或代码审查中先验证契约。两条路径都将冷构建状态视为声明，不执行命令、不联网，也不把 `passed` 解释为本地运行证明。

### 数据契约

- `RepoSnapshot`：仓库元数据、贡献计数、依赖名、工作流名、CODEOWNERS 规则和发布配置路径。它们是观测信号，不等同于当前权限或应急能力。
- `Finding`：严重程度、标题、证据说明和操作建议。建议是人工待验证事项，不应暗示操作已执行。
- `DrillResult`：场景标识、启发式分数、置信度、假设、指标、结构化 Evidence、发现和时间线。报告应同时展示假设与结论。

分数只允许比较同一规则版本、同一采集范围下的改进前后结果；基线门禁会拒绝跨规则版本比较，不用于跨项目榜单。提交数不是工作量；存在发布配置不证明备用维护者拥有发布权限；存在 CODEOWNERS 不证明规则覆盖关键文件或成员仍活跃。

CLI 在报告写入前加载 baseline，并将已校验的快照传给比较器；这保证 baseline 与输出目录相同的连续运行不会因原子替换而把旧报告误读成当前报告。

## 已实现原型与目标架构

当前原型由静态快照触发预定义事故叙述，并对维护者、依赖与 CI 场景运行确定性的工作队列模拟。每个适用场景会同时报告事故窗口内的峰值/结束积压，以及事故结束后固定七天、基于明确容量假设的恢复窗口；这仍不是经过实证校准的事故概率，也没有真实验证冷构建、人员可用性或故障恢复。对外应明确这个边界。

真正的演练引擎按以下顺序推进：

1. **带出处的快照**：每条事实附带来源、采集范围和缺失原因，区分未知与确实不存在。贡献者身份仅作局部标识，不做个人排名。
2. **显式能力模型**：把审查、合并、构建、签名、发布等操作表示为能力节点；人员角色和基础设施提供能力，仓库文件仅提供证据。用户可以补充或更正这些假设。
3. **事故与事件队列**：事故使某些能力不可用；事件按时间推进状态，只在先决条件满足时执行。排队增长、恢复和替代路径必须由输入与规则产生，不能只更换时间线文案。
4. **反事实方案比较**：同一快照分别运行基线和改进方案，解释备用审查者、本地构建或恢复 Runbook 改变了哪个阻塞点。
5. **恢复工件草稿**：生成待审查的清单和 Runbook。写入 Issue、PR 或权限始终需要用户显式授权。

目标场景接口为“快照 + 事故参数 + 模型版本 → 结果”。如果将来引入随机分布，种子、分布及敏感性分析必须保存在报告中；缺少校准样本时不得输出看似精确的概率。

## 安全与隐私边界

- 仓库视为不可信输入：不导入其 Python 模块，不执行 npm hooks、Makefile 或工作流，不把文件内容拼接成 shell 命令。
- 本地分析不需要 GitHub token。未来 API 采集器默认只读，令牌不进入快照、报告、日志或缓存。
- `.npmrc`、`.pypirc` 等配置默认只检查路径存在性，不把潜在凭证内容写入报告。
- 报告默认只在本地生成；启用 `privacy.anonymize_people` 和 `privacy.anonymize_repository` 后，贡献者/CODEOWNERS 身份会被替换，仓库名变为稳定短摘要、路径变为 `<local-repository>`。依赖名仍可能属于私有命名空间，公开分享前必须人工审查。
- 每份由 CLI 生成的报告都可包含 `privacy` 摘要，分别标明人员身份、仓库身份是否匿名化，并固定记录 `upload_repository_content: false`；该摘要不携带原始姓名、owner、路径或映射表。
- 报告 API 也执行同一 fail-closed 契约：即使绕过 CLI，`upload_repository_content: true` 仍会被拒绝，不会生成与实际策略矛盾的摘要。
- 报告与恢复 API 共享快照投影校验；声明 `anonymize_people` 或 `anonymize_repository` 时，若传入快照仍含原始身份/路径会直接拒绝，且不会先创建输出目录。
- 不把私有仓库工件发布为公开 badge、排名或公开基准样本。需要公开分享时应生成单独的脱敏摘要。
- 未来外部来源读取要设置超时、大小与分页上限；链接与 HTML 输出要转义；符号链接不得让扫描范围悄悄越过仓库边界。当前分析器对依赖清单、CODEOWNERS、工作流和发布文件执行解析后仓库内检查。

配置项不能仅靠写入示例文件就被宣称为已生效。CLI 必须读取、验证并执行配置；未知顶层字段和未知 `privacy` 选项会被拒绝，尚未实现的选项不得静默忽略。

## 发布验收清单

| 方面 | 必须验证 |
| --- | --- |
| 采集准确性 | 非 Git 目录、空历史、浅克隆、缺失 Git、格式错误的依赖文件均不伪装成完整数据；损坏的 `package.json` 以输入错误拒绝 |
| 场景边界 | 无贡献者、无依赖、无工作流时区分未知、不适用和低风险；时间线有序且不超出演练窗口 |
| 可复现性 | 同一快照与参数重复运行结果相同；集合与身份映射顺序稳定 |
| 可解释性 | 所有结论可追溯到输入；假设进入 JSON 和可读报告；评分规则版本可识别 |
| 输出安全 | HTML 特殊字符安全转义；报告不包含凭证；匿名化启用时不漏出原始身份 |
| CLI | 错误参数返回非零退出码；不覆盖用户配置；输出路径行为有文档和测试 |
| CI | Windows 与 Ubuntu 运行同一核心测试；GitHub 集成使用最小权限 |
| 产品诚实性 | README 清晰区分已实现能力与路线图；不声称“全球首创”或已证明恢复能力 |

新增场景需要提供一对最小样例：确实存在阻塞的样例，以及看起来相似但有已验证备用路径的负例。若修复措施不能改变结果，必须说明原因，不能为了展示改进而调高分数。

## 有意暂不引入的复杂性

首版不引入 LLM 自动判断、后台常驻服务、数据库、组织级排名、真实权限修改、无人监督发布或任意插件执行。先把证据准确性、事件模型和反事实解释做扎实，再增加分发渠道与界面。
